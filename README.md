# Shorty - URL Shortener

by Beto Carlos

## Implementation Details

This simple app uses React's Server Actions and Next's middleware.

It has 2 main parts:

1. Creating the short URL
2. Redirecting to the original url with the short url.

### 1. Creating the short URL

1. The UI has a simple form that accepts the original URL. The form uses HTML validation with the `required` and `type=url` attributes. It won't submit the form until there's a valid URL on the input.
2. Once the form is submitted, it uses `useFormState` to call a server action (`createShortUrl`) on the actions.ts file.
3. Zod handles server validation. The parse function will throw if the data object does not fulfill the schema (id: needs to be a string and 6 characters long; URL: needs to be a URL).
4. The data object consists of the url (passed through the `formData` parameter) and an id.
5. The id is generated by a util function `genUniqueId` (`utils.ts`). This function leverages the [Sqids](https://sqids.org/) package.
6. Once the id is generated, it saves it to a Redis Database\*.
7. If everything is successful, the function will return an object with a success property and a message. If not, it will return an object with a non-successful property and a message.
8. We capture the message from the server action through the `useFormState` hook and pass it to a Messages component that displays the message.

\*Why Redis? I know that the requirements stated that server memory would suffice, but I had a hard time persisting the data across server instances since Next's server is supposed to be stateless. So, instead of getting into that rabbit hole, I opted for the path of least resistance and fired up a simple [Upstash](https://upstash.com/docs/introduction) Redis Database.

### 2. Redirecting

1. The redirect is possible through Next's Middleware.
2. We configure a `matcher` array so the middleware does not run through Next's routes.
3. We get the pathname (which should be the id of step 1 and a slash at the beginning) and remove the initial slash to get the id.
4. Once we have that, we can simply call our Redis DB to get the original URL and redirect to that URL.
5. If the pathname does not match anything on our Redis Database, the middleware continues without redirecting.

## How to Run

1. Install Dependencies

```
pnpm install
```

2. Start development server

```
pnpm dev
```


## Testing

Alas, due to the time constraint, I didn't have time to do any automated testing. I was planning to add at least two tests:

-   Unit tests the `genUniqueId` function on the `utils.ts` file.
-   E2E testing with Playwright, making sure the flow works.

I manually tested the whole app and put some rail guards with HTML and server validation (`Zod`). On the `actions.ts` file, you can comment on `line 17` and uncomment `line 16` to mimic an error and see how the app behaves when an error is encountered in that server action.

## Tools Used

-   Next: React Framework
-   Tailwind: Styling
-   Sqids and Lodash: To generate random unique ids (for the short url slug)
-   Zod: Server Validation
-   Lucide: Icons
-   ChatGPT: Mainly to unstuck myself. I wanted to learn how to persist data across different server instances in Next.js. ChatGPT wasn't helpful, and I was getting stuck, so I decided to use Redis.
-   Upstash Redis: To persist data and have a dictionary of `id: originaUrl`
